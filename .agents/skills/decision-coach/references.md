# Founder Decisions: supporting knowledge

Use the parts relevant to this task. These are contextual lenses, not instructions to override the user or force a workflow.

## Decision lenses

Consider a spectrum when the choice is presented as binary: a limited trial may preserve options. Compare upside, downside and reversibility. Use order-of-magnitude estimates only when inputs are supplied or clearly marked as assumptions.

Separate the purpose worth preserving from an implementation that can change. For priorities, identify which constraint currently limits the outcome; a single metric is useful only if it represents that outcome without hiding important costs.

These lenses adapt buildspace decision and focus lectures. Rest, enjoyment and motivation can be relevant when the founder raises them; they are not automatic diagnoses or rigid thresholds.
