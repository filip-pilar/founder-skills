# Product Scope: supporting knowledge

Use the parts relevant to this task. These are contextual lenses, not instructions to override the user or force a workflow.

## A useful first version

The toy-version question is a way to identify the smallest useful experience, not permission to ship a broken core flow. Start with one person's job and a clear input → useful result path. Cut adjacent ambitions before removing the essentials that make the result trustworthy.

A deadline can focus choices, but arbitrary urgency may hide dependencies. Name external requirements and leave time to observe use and repair defects. Distinguish work that enables learning from polish that does not affect the current question.

Adapted from buildspace lessons on shipping and useful/usable/beautiful. The original stories illustrate tradeoffs; they do not prove that every product should ship in seven days.
